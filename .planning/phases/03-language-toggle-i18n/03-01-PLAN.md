<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser localStorage → app | persisted `language` value is attacker-controllable via devtools/other scripts |
| navigator.language → app | browser-provided locale string read at init |
| server-rendered HTML → injected inline script | `languageInitScript` runs via dangerouslySetInnerHTML before hydration |
| npm registry → build | new third-party packages (i18next, react-i18next) enter the dependency tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `languageInitScript` injected via dangerouslySetInnerHTML in app/root.tsx | high | mitigate | Zero-interpolation static script: only the compile-time `LANGUAGE_STORAGE_KEY` constant is embedded (no runtime/user value is interpolated into the script string), mirroring the audited theme script (T-02-02). No `navigator.language` value is written into the script source — it is read at runtime inside the IIFE. |
| T-03-02 | Tampering | persisted `language` in localStorage read by usePersistedPreference + blocking script | low | accept | Value is validated against `["pt","en"]` (hook validValues; blocking script validates before use) and falls back to detection when invalid; a bad value can only select an existing language, never inject markup. |
| T-03-03 | Injection (XSS) | translation strings rendered through t() in JSX | low | accept | All translation content is static and author-controlled (no user input), and react-i18next/React escape by default with `interpolation.escapeValue:false` only affecting React-escaped JSX. Constraint for all plans: render translations as plain t() text — do NOT pass them through dangerouslySetInnerHTML or `<Trans>` with raw HTML. |
| T-03-SC | Tampering (supply chain) | `npm install i18next react-i18next` | high | mitigate | Blocking human-verify checkpoint (Task 2 predecessor) confirms both packages on npmjs.com are the official i18next-org packages before install; lockfile pins resolved versions. |

No high-severity threat is left unmitigated (ASVS L1; block-on=high satisfied).
</threat_model>
