## Directory Purposes

**`app/`:**
- Purpose: All application source code
- Contains: React components, routing, styling, constants, assets
- Key files: `root.tsx` (entry point), `routes.ts` (route definitions)

**`app/routes/`:**
- Purpose: Page-level route components
- Contains: One file per route (currently just `home.tsx` for index route)
- Key files: `home.tsx` (renders all feature sections)

**`app/features/`:**
- Purpose: Self-contained feature modules representing portfolio sections
- Contains: 6 feature directories (Header, Hero, Projects, AboutMe, Contacts, Footer)
- Pattern: Each feature has `index.tsx` (component), `data.tsx` (constants), `types.tsx` (types)

**`app/features/Header/`:**
- Purpose: Navigation header with mobile menu
- Contains: Sticky header with logo, nav links, CV download
- Key files: `index.tsx` (component with menu state), `types.tsx` (button prop types)

**`app/features/Hero/`:**
- Purpose: Hero/intro section with profile and headline
- Contains: Profile image, name, job title, tech stack, CTA buttons
- Key files: `index.tsx` (component), `data.tsx` (techs array), `types.tsx` (button types)

**`app/features/Projects/`:**
- Purpose: Projects showcase section
- Contains: Grid of project cards with descriptions, tech, and links
- Key files: `index.tsx` (grid component), `data.tsx` (projects array), `types.tsx` (project card props)

**`app/features/AboutMe/`:**
- Purpose: About/professional background section
- Contains: Education, experience, skills, courses
- Key files: `index.tsx` (component), `data.tsx` (exp/education/skills arrays), `types.tsx` (card types)

**`app/features/Contacts/`:**
- Purpose: Contact methods section
- Contains: WhatsApp, email, LinkedIn contact cards
- Key files: `index.tsx` (component only, uses CONTACTS constant)

**`app/features/Footer/`:**
- Purpose: Footer with copyright
- Contains: Copyright notice with year
- Key files: `index.tsx` (simple footer component)

**`app/shared/`:**
- Purpose: Reusable components used by multiple features
- Contains: Generic UI components
- Key files: `TechBadge.tsx` (icon + label for technologies)

**`app/constants/`:**
- Purpose: Centralized configuration and constants
- Contains: Contact information, URLs, personal details
- Key files: `index.tsx` (exports `CONTACTS` object with email, phone, links, CV URL)

**`app/assets/`:**
- Purpose: Static media files
- Contains: Images used in components
- Subdirectories:
  - `assets/projects/` - Project thumbnail images
  - Root: `profile.png` (profile photo)

**`public/`:**
- Purpose: Static files served as-is by web server
- Contains: Favicon, robots.txt, etc.
- Note: Generated Vite assets go here during build

## Naming Conventions

**Files:**
- React components: PascalCase (e.g., `Hero.tsx`, `TechBadge.tsx`)
- Route files: kebab-case (e.g., `home.tsx`, `routes.ts`)
- Data/config files: `data.tsx`, `types.tsx`, `index.tsx` (specific purpose names)
- CSS: `app.css` (global styles)

**Directories:**
- Features: PascalCase (e.g., `app/features/Hero/`, `app/features/Projects/`)
- Utilities: lowercase (e.g., `app/shared/`, `app/routes/`, `app/assets/`)
- Subdirectories: lowercase (e.g., `assets/projects/`)

**TypeScript/JavaScript:**
- Components: PascalCase (e.g., `export default function Hero()`)
- Functions: camelCase (e.g., `closeMenu()`, `map()`)
- Variables: camelCase (e.g., `isMenuOpen`, `techs`, `projects`)
- Types: PascalCase (e.g., `ButtonProps`, `ProjectContainerProps`, `Experience`)
- Constants: UPPER_SNAKE_CASE (e.g., `CONTACTS`, imported from `app/constants`)
- Data arrays: camelCase plural (e.g., `techs`, `projects`, `experiences`)

**CSS Classes:**
- Tailwind utilities: lowercase hyphenated (e.g., `flex`, `items-center`, `bg-purple-500`)
- Custom classes: Not used (Tailwind utility-first approach)

## Where to Add New Code

**New Feature Section (e.g., Blog, Speaking):**
1. Create directory: `app/features/NewFeature/`
2. Add component: `app/features/NewFeature/index.tsx` (main JSX)
3. Add data: `app/features/NewFeature/data.tsx` (static data arrays)
4. Add types: `app/features/NewFeature/types.tsx` (TypeScript types)
5. Import in: `app/routes/home.tsx` (add `<NewFeature />` in render)
6. Add hash link in: `app/features/Header/index.tsx` (header nav and mobile menu)

**New Reusable Component (e.g., Card, Button):**
1. Create file: `app/shared/ComponentName.tsx`
2. Define component with TypeScript props
3. Import and use in multiple features

**New Shared Constant:**
1. Add to: `app/constants/index.tsx` (in `CONTACTS` object or new export)
2. Import where needed: `import { CONSTANT_NAME } from "~/constants"`

**New Static Asset (Image):**
1. Place in: `app/assets/` or `app/assets/projects/`
2. Import in component: `import photo from "~/assets/photo.png"`
3. Use in JSX: `<img src={photo} alt="..." />`

**New Type Definition:**
1. If feature-specific: `app/features/Feature/types.tsx`
2. If shared: Create `app/shared/types.ts`
3. Export and import where needed

## Special Directories

**`.react-router/`:**
- Purpose: Generated type definitions by React Router
- Generated: Yes (auto-generated during build/dev)
- Committed: No (in .gitignore)
- Contains: Type stubs for route configurations and meta

**`node_modules/`:**
- Purpose: Installed npm dependencies
- Generated: Yes (from package-lock.json or yarn.lock)
- Committed: No (in .gitignore)

**`.vscode/`:**
- Purpose: VS Code workspace settings
- Generated: No (developer config)

**`.planning/codebase/`:**
- Purpose: GSD codebase analysis documents
- Generated: No (manually created analysis)
- Committed: Yes

**`dist/` or `build/`:**
- Purpose: Compiled production build output
- Generated: Yes (from `npm run build`)
- Committed: No (in .gitignore)

## Path Aliases

TypeScript path alias configured in `tsconfig.json`:
```json
{
  "compilerOptions": {
    "paths": {
      "~/*": ["./app/*"]
    }
  }
}
```

This allows imports like:
- `import Hero from "~/features/Hero"` instead of `import Hero from "../features/Hero"`
- `import { CONTACTS } from "~/constants"` instead of `import { CONTACTS } from "../../../constants"`

Always use the `~/` alias for app-internal imports.
